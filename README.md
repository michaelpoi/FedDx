# FedDx — Gemma 4 Diagnosis Classification

FedDx evaluates diagnosis prediction from **clinician-style summaries generated by an LLM from synthetic DDXPlus patient records**. The current experiment compares pretrained **`google/gemma-4-12B-it`** with Gemma 4 12B adapted using **4-bit QLoRA**.

> **Research only.** The source records are synthetic, and the generated summaries have not been clinically validated. Results below do not establish performance on real patients.

## Data

| Split | Cases | Sampling | File |
|---|---:|---|---|
| Train | 5,000 | Hybrid: moderately upweights rarer diagnoses | `data/generated_clinical_v2/train.jsonl` |
| Validation | 1,000 | Natural sampling | `data/generated_clinical_v2/validate.jsonl` |
| Test | 2,000 | Natural sampling | `data/generated_clinical_v2/test.jsonl` |

All summaries use the `clinician-v2` generation prompt. Diagnosis targets and differential-diagnosis fields are **not** exposed to the summary-generation model. For diagnosis fine-tuning, only `clinical_summary` is given as input; `target.diagnosis` is used as the supervised completion. The training data has 49 diagnosis classes; 47 of those occur in the sampled validation set.

The training subsets are deterministically selected by the training script from the available 5,000 examples using seed 42; 1k is nested within 3k, which is nested within 5k. The source train/validation/test files are separate; source-level and near-duplicate leakage checks remain recommended.

## Validation results

**These are results on the 1,000-case validation set, not the held-out test set.**

### Open-ended diagnosis generation (strict DDXPlus label matching)

| Model | Training | Accuracy | Macro-F1 (47 validation classes) | Out-of-vocabulary responses |
|---|---|---:|---:|---:|
| Vanilla Gemma 4 12B | None | 19.8% | 23.15% | 743 / 1,000 |
| QLoRA 1k | Independent, 1,000 examples, 2 epochs | 87.6% | 87.20% | 39 / 1,000 |
| **QLoRA 5k** | **Independent, 5,000 examples, 2 epochs** | **97.9%** | **98.03%** | **0 / 1,000** |
| QLoRA 3k | Progressive continuation from 1k | 0.0% | 0.0% | 1,000 / 1,000 |

The **progressive 3k experiment failed** and is not evidence that training on 3,000 examples is inherently worse. It began from the trained 1k adapter, continued with an additional 376 optimizer steps at learning rate `2e-4`, and started generating only the `<turn|>` token. Its teacher-forced validation loss rose sharply between steps 200 and 250 (0.0205 → 4.1623). The failure mechanism was not conclusively identified. Do **not** use this failed adapter as a valid learning-curve point or as initialization for further training.

### Open-ended generation with conservative diagnosis-name normalization

| Model | Accuracy | Macro-F1 | Out-of-vocabulary responses |
|---|---:|---:|---:|
| Vanilla Gemma 4 12B | 23.1% | 26.55% | 705 / 1,000 |

Conservative normalization resolved 38 vanilla predictions, making 33 additional predictions correct. It does **not** treat distinct diagnoses (e.g. pleurisy vs pulmonary embolism) as equivalent. Normalized scores for the fine-tuned adapters have not been provided and are intentionally omitted.

### Closed-set, 49-candidate diagnosis likelihood scoring

| Model | Accuracy | Macro-F1 (47 present classes) | Macro-F1 (all 49 classes) | Balanced accuracy (present classes) | Invalid |
|---|---:|---:|---:|---:|---:|
| Vanilla Gemma 4 12B | 67.1% | 61.70% | Not reported | Not reported | 0 |
| QLoRA 1k | 79.7% | 73.19% | 70.20% | 76.53% | 0 |
| **QLoRA 5k independent** | **83.7%** | **79.30%** | **76.06%** | **81.45%** | **0** |

**Important evaluation caveat:** Open-ended greedy generation and closed-set candidate ranking are **different prediction rules**. The closed-set scorer used mean token log-probability, and its results do not reproduce the open-ended outputs. On the independent 5k adapter, there were 146 disagreeing predictions; frequent closed-set confusions included Stable → Unstable angina (29), URTI → Influenza (16), and PSVT → Panic attack (11). A targeted diagnostic on three Stable-angina cases favored the correct label under **both** total and mean log-probability when scored under a training-matched prompt. This did **not** support length normalization as the cause for those three errors; prompt differences or other scorer implementation details still require investigation. Avoid claiming the closed-set result measures exactly the same task as open-ended generation.

## Training configuration

The successful 1k run used Gemma 4 12B with NF4 4-bit QLoRA, BF16 computation where supported, LoRA rank 16, alpha 32, dropout 0.05, adapters on text attention and MLP projections (`q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj`), micro-batch 1, gradient accumulation 16, sequence length 1,024, and 2 epochs. Its learning rate was `2e-4` and it completed 126 optimizer steps.

The independent 5k experiment was launched separately from the original base model, rather than from the 1k or failed progressive 3k adapter. Check `runs/gemma4_qlora_independent/stage-5000/run_manifest.json` for its exact saved hyperparameters before reporting them as confirmed; the independent 5k run used a modified configuration and its complete manifest was not supplied in this conversation.

Adapter paths:

- 1k: `runs/gemma4_qlora/stage-1000/adapter_final`
- Failed progressive 3k: `runs/gemma4_qlora/stage-3000/adapter_final`
- Successful independent 5k: `runs/gemma4_qlora_independent/stage-5000/adapter_final`

## Reproduce open-ended evaluation

Evaluate on validation:

```bash
uv run python src/evaluate_gemma4_diagnoses.py \
  --model-id vanilla

uv run python src/evaluate_gemma4_diagnoses.py \
  --model-id 5000 \
  --adapter-root runs/gemma4_qlora_independent \
  --output-root runs/gemma4_evaluation_independent
```

Evaluate on the **held-out test set** using the same open-ended protocol:

```bash
uv run python src/evaluate_gemma4_diagnoses.py \
  --model-id vanilla \
  --split test \
  --output-root runs/gemma4_evaluation_test

uv run python src/evaluate_gemma4_diagnoses.py \
  --model-id 5000 \
  --split test \
  --adapter-root runs/gemma4_qlora_independent \
  --output-root runs/gemma4_evaluation_test
```

Predictions are stored incrementally and reused when an evaluation is rerun with identical configuration. Results include `predictions.jsonl`, `metrics.json`, per-class classification reports, and confusion matrices. The open-ended protocol requires an exact DDXPlus label (unless conservative normalization is reported separately), so out-of-vocabulary responses count as incorrect.

## Status and limitations

- **Completed:** 5k training set, 1k validation set, 2k held-out test set; independent 1k and 5k adapters; validation open-ended and closed-set comparisons.
- **Not yet reported:** actual held-out **test** accuracy and macro-F1 for vanilla and independent 5k. Do not copy validation results into the test table.
- The observed validation performance may exploit patterns or shortcuts in synthetic DDXPlus and LLM-generated summaries. Check exact/near duplicates across source splits and diagnosis mentions in legitimate medical history; do not remove legitimate history solely because it mentions a disease.
- An independent 3k model with successful evaluation has **not** been reported. The failed progressive 3k run is not comparable to independent 1k/5k training.
- Training loss measures teacher-forced response-token likelihood and should be supplemented with actual generated predictions; the progressive 3k run demonstrated why this matters.
