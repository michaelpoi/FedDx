# FedDx — Explainable Diagnosis Prediction with LLMs

FedDx predicts a differential diagnosis from clinician-style summaries generated by an LLM from synthetic **DDXPlus** patient records, and treats the explanation as something to be **tested**, not merely displayed.

The system compares pretrained **`google/gemma-4-12B-it`** with Gemma 4 12B adapted using **4-bit QLoRA**, then adds three layers of evidence on top of the prediction: a calibrated confidence score, a clinician-deferral policy, and SHAP attributions whose faithfulness is measured.

> **Research only.** The source records are synthetic and the generated summaries have not been clinically validated. Nothing here establishes performance on real patients.

---

## Pipeline

| Stage | What happens | Code |
|---|---|---|
| 1. Raw patient record | DDXPlus structured evidence: age, sex, and clinical evidence as question/answer pairs | `src/preprocess_ddxplus.py` |
| 2. Clinical case generation | Gemma 4 rewrites the structured evidence into a clinician-style summary | `src/generate_clinical_cases.py` |
| 3. Prediction | Gemma 4 12B + QLoRA adapter generates a diagnosis as free text | `src/evaluate_gemma4_diagnoses.py` |
| 4. Confidence + explanation | Calibrated confidence, deferral zone, and phrase-level SHAP | `src/feddx_confidence.py`, `src/feddx_deferral.py`, `src/feddx_shap.py` |

## Data

| Split | Cases | Sampling | File |
|---|---:|---|---|
| Train | 5,000 | Hybrid: moderately upweights rarer diagnoses | `data/generated_clinical_v2/train.jsonl` |
| Validation | 1,000 | Natural sampling | `data/generated_clinical_v2/validate.jsonl` |
| Test | 2,000 | Natural sampling | `data/generated_clinical_v2/test.jsonl` |

All summaries use the `clinician-v2` generation prompt. Diagnosis targets and differential-diagnosis fields are **not** exposed to the summary-generation model. For diagnosis fine-tuning, only `clinical_summary` is given as input; `target.diagnosis` is the supervised completion. The training data has 49 diagnosis classes; 47 occur in the sampled validation set.

Training subsets are deterministically selected by the training script from the 5,000 examples using seed 42; 1k is nested within 3k, which is nested within 5k. Source train/validation/test files are separate; source-level and near-duplicate leakage checks remain recommended.

### Clinical case generation

Each summary has three sections — `Patient`, `Presenting findings`, `Relevant history` — for example:

> Patient: 41-year-old male.
> Presenting findings: The patient reports a high-pitched sound during inhalation.
> Relevant history: The patient has a history of cigarette smoking and a diagnosis of gastroesophageal reflux.

This step exists because a list of yes/no evidence codes is weak input for a language model. The generated summary is what the classifier reads.

## Fine-tuning

NF4 4-bit QLoRA on Gemma 4 12B, BF16 computation where supported, LoRA rank 16, alpha 32, dropout 0.05, adapters on text attention and MLP projections (`q_proj`, `k_proj`, `v_proj`, `o_proj`, `gate_proj`, `up_proj`, `down_proj`), micro-batch 1, gradient accumulation 16, sequence length 1,024, 2 epochs. The 1k run used learning rate `2e-4` and completed 126 optimizer steps.

The independent 5k experiment was launched separately from the base model, not continued from the 1k or the failed progressive 3k adapter. Check `runs/gemma4_qlora_independent/stage-5000/run_manifest.json` for its exact saved hyperparameters before reporting them as confirmed.

Adapter paths:

- 1k: `runs/gemma4_qlora/stage-1000/adapter_final`
- Failed progressive 3k: `runs/gemma4_qlora/stage-3000/adapter_final`
- Independent 5k: `runs/gemma4_qlora_independent/stage-5000/adapter_final`

## Evaluation

**Results below are on the 1,000-case validation set, not the held-out test set.**

### Open-ended diagnosis generation (strict DDXPlus label matching)

| Model | Training | Accuracy | Macro-F1 (47 validation classes) | Out-of-vocabulary |
|---|---|---:|---:|---:|
| Vanilla Gemma 4 12B | None | 19.8% | 23.15% | 743 / 1,000 |
| QLoRA 1k | Independent, 1,000 examples, 2 epochs | 87.6% | 87.20% | 39 / 1,000 |
| **QLoRA 5k** | **Independent, 5,000 examples, 2 epochs** | **97.9%** | **98.03%** | **0 / 1,000** |
| QLoRA 3k | Progressive continuation from 1k | 0.0% | 0.0% | 1,000 / 1,000 |

The out-of-vocabulary column carries the main finding: the base model does not fail for lack of medical knowledge, it fails by answering outside the label set — for example `HIV` instead of `HIV (initial infection)`. Fine-tuning teaches the output space and format.

The **progressive 3k experiment failed** and is not evidence that training on 3,000 examples is inherently worse. It began from the trained 1k adapter, continued for 376 additional optimizer steps at learning rate `2e-4`, and started generating only the `<turn|>` token. Its teacher-forced validation loss rose sharply between steps 200 and 250 (0.0205 → 4.1623). The failure mechanism was not conclusively identified. Do **not** use this adapter as a learning-curve point or as initialization. The lesson: training loss measures teacher-forced likelihood and must be checked against actually generated predictions.

### Open-ended generation with conservative diagnosis-name normalization

| Model | Accuracy | Macro-F1 | Out-of-vocabulary |
|---|---:|---:|---:|
| Vanilla Gemma 4 12B | 23.1% | 26.55% | 705 / 1,000 |

Normalization resolved 38 vanilla predictions, making 33 additional predictions correct. It does **not** treat distinct diagnoses (e.g. pleurisy vs pulmonary embolism) as equivalent. Normalized scores for the fine-tuned adapters are intentionally omitted.

### Closed-set, 49-candidate diagnosis likelihood scoring

| Model | Accuracy | Macro-F1 (47 present) | Macro-F1 (all 49) | Balanced accuracy | Invalid |
|---|---:|---:|---:|---:|---:|
| Vanilla Gemma 4 12B | 67.1% | 61.70% | Not reported | Not reported | 0 |
| QLoRA 1k | 79.7% | 73.19% | 70.20% | 76.53% | 0 |
| **QLoRA 5k independent** | **83.7%** | **79.30%** | **76.06%** | **81.45%** | **0** |

**Evaluation caveat — read before quoting a baseline.** Open-ended greedy generation and closed-set candidate ranking are **different prediction rules**. Compare *within* a row, never across rows: 19.8% → 97.9% open-ended, or 67.1% → 83.7% closed-set. The closed-set scorer used mean token log-probability and does not reproduce the open-ended outputs. On the independent 5k adapter there were 146 disagreeing predictions; frequent closed-set confusions were Stable → Unstable angina (29), URTI → Influenza (16), PSVT → Panic attack (11). A targeted diagnostic on three Stable-angina cases favoured the correct label under both total and mean log-probability when scored with a training-matched prompt, which did **not** support length normalization as the cause; prompt differences or scorer implementation details still require investigation.

## Confidence scores

Confidence for one prediction is the **geometric-mean probability of the generated diagnosis tokens**. It describes a single output, and is not an F1, RMSE or perplexity — those benchmark a whole model on a whole dataset.

Raw scores are heavily saturated, so they are calibrated with **Platt scaling**: a logistic regression fitted on the *logit* of the raw score, `P(correct) = sigmoid(a · logit(score) + b)`, fitted on the calibration split only.

| Metric | Raw | Platt-calibrated |
|---|---:|---:|
| ECE | 0.017 | 0.014 |
| Brier | 0.018 | 0.017 |
| AUROC (correct vs wrong) | 0.972 | — |

Calibration changes the scale, not the ranking; AUROC 0.972 shows the ranking was already informative. The distribution stays concentrated — roughly 900 of 962 scored cases sit near 1.0 and are all correct, with errors in the thin tail below 0.95. That concentration is why a small review budget is enough.

Outputs: `reliability_diagram.png`, `risk_coverage.png` (with its AURC summary), `trust_metrics.json`.

## Deferral: when does a clinician take over?

Three zones, defined in `src/feddx_deferral.py`:

| Zone | Condition | Action |
|---|---|---|
| `AUTO_ACCEPT` | calibrated p ≥ accept threshold | accepted automatically; logged and sample-audited |
| `REVIEW` | stop ≤ p < accept | prediction and SHAP evidence shown to a clinician, who confirms or overrides |
| `SAFE_STOP` | p < stop threshold, invalid label, or no score | no model diagnosis shown; route to standard clinical workup |

The accept threshold is **not** chosen by hand. `evaluate_trust.py` takes the lowest threshold whose accepted calibration cases have a **Wilson 95% lower bound on accuracy ≥ `--target-accuracy`** (default 0.95), subject to `--min-accept-n` (default 30). The guarantee is on the lower bound, not the point estimate. Default stop threshold is 0.5.

Thresholds are fitted on validation; the table below is on the held-out test set.

| Policy target | Auto-accept | Review | Safe stop | Silent errors per 1,000 |
|---:|---:|---:|---:|---:|
| 0.95 | 95.0% | 1.2% | 3.9% | 21 |
| 0.98 | 92.4% | 3.8% | 3.8% | 8 |
| 0.99 | 91.7% | 4.5% | 3.8% | 4 |

A **silent error** is a wrong prediction that is auto-accepted and shown without a flag — the dangerous failure mode. Reviewing 4.5% of cases cuts silent errors from 21 to 4 per 1,000.

A **safe stop** is an answer outside the 49 labels, for example `HIV` instead of `HIV (initial infection)`. It is never displayed as a diagnosis.

## SHAP for explainability

`src/feddx_shap.py` computes phrase-level permutation SHAP over the clinical summary.

- **Attributed quantity:** the teacher-forced log-likelihood of the **already predicted** diagnosis. The prediction is held fixed; SHAP does not re-run it.
- **Units:** log-likelihood (nats), not probability.
- **Features:** contiguous text clauses, split on `, ; . ! ?` and newlines. The splitter asserts that re-joining the chunks reproduces the original text exactly, so segmentation is lossless. Default 12 chunks, adjustable 4–24 in the app.
- **Baseline:** the empty summary — every clause removed.
- **Algorithm:** `shap.Explainer(..., algorithm="permutation")` with a fixed seed, budget `(2n+1) × permutations` model evaluations, with coalition caching.
- **Rendering:** red supports the predicted label, blue opposes it, intensity is relative magnitude.
- **Self-check:** every explanation returns an `additivity_error` — `|baseline + Σ(SHAP) − full score|`. Shapley values must sum exactly to the difference between full and baseline, so a small error shows the approximation converged.

Scoring uses the same chat rendering as training (a completed assistant turn) rather than `add_generation_prompt=True`, which on Gemma can open a thought channel. A marker string locates the diagnosis span, which is mapped to exact token positions so only those log-probabilities are summed.

**Scope.** SHAP here describes model behaviour. It does not attribute clinical correctness, does not provide calibrated confidence, and does not establish causality.

## Is SHAP faithful?

A highlight that looks plausible is not evidence the model used it. `src/shap_faithfulness.py` runs a **deletion (comprehensiveness) test**.

For each case, for k = 1..3, it removes the top-k SHAP clauses, k random clauses (averaged over repeats), and the bottom-k SHAP clauses as a sanity control, then measures

`drop = log P(full summary) − log P(summary without those clauses)`

and optionally re-generates to record whether the predicted label changes. It reports a paired bootstrap CI (2,000 resamples) and a one-sided Wilcoxon test of top versus random.

| Measurement | Value |
|---|---:|
| Cases evaluated | 97 |
| Diagnosis changes after removing top-3 SHAP clauses | 30% |
| Diagnosis changes after removing 3 random clauses | 3% |
| Significant from | k = 2, p < 0.001 |
| Runtime per explanation | ~11 s |

**Why the flip rate is 30% and not higher.** The generated summaries repeat evidence — the same symptom often appears in more than one clause — so deleting a single clause rarely removes the information from the case. This is why single clauses rarely matter and the effect only reaches significance from k = 2, and it makes 30% a lower bound on faithfulness rather than a ceiling.

`src/xai_analysis.py` adds a stricter variant, **contrastive SHAP and contrastive deletion**, which attributes the margin `log P(prediction) − log P(rival)` and asks whether removing the top contrastive clauses *reverses* that margin. The rival is the true label when the model is wrong, the runner-up otherwise. This addresses the limitation that standard SHAP explains the likelihood of a label but not why it beat the alternatives.

Outputs: `faithfulness_report.md`, `deletion_curve.png`, `cases.jsonl`, `summary.json`.

## Subgroup check

`evaluate_trust.py` reports accuracy and deferral rates per subgroup on the evaluation split. Groups are formed on **sex** and on **age band** (`0-17`, `18-39`, `40-64`, `65+`), with a minimum group size of 30; smaller groups are flagged and drawn in grey.

| Measurement | Value |
|---|---:|
| Accuracy gap by sex | 1.5 pp |
| Accuracy gap by age | 3.4 pp |
| 95% confidence intervals | all overlap |
| Auto-accept parity index (sex) | 0.96 |
| Auto-accept parity index (age) | 0.97 |
| Review rate, female vs male | 10% vs 6% |

Two distinct measures, kept separate deliberately:

- **Predictive parity** — equal prediction *quality* across groups, measured as the accuracy gap with Wilson 95% intervals. The intervals overlap, so the gaps are not distinguishable from noise.
- **Group parity index** — `P(favourable | group A) / P(favourable | group B)`, with auto-accept treated as the favourable fast path. 1.00 means equal.

Also reported per group: `auto_accept_rate_given_correct` as an equal-opportunity analogue, and `silent_errors`.

**The finding worth noting is the review rate.** Female cases are routed to clinician review almost twice as often as male cases. Equal accuracy does not mean equal burden — in deployment this is unequal clinician workload, which is a property of the system rather than of the model alone.

`src/xai_analysis.py` adds a mechanism check alongside the rates: it reports what share of SHAP attribution comes from demographics versus presenting findings versus history per diagnosis, and flags cases where the age-and-sex line is the largest contributor (`demographics_top_supporting_feature`) or where the diagnosis name appears literally in the top clause (`predicted_label_literal_in_top_feature`, i.e. label leakage from the generation step).

**Caveat:** the patients are synthetic and `sex` is a dataset source code, not self-reported gender. This demonstrates the method, not real demographic performance.

## Conclusion

| Claim | Evidence |
|---|---|
| Fine-tuning closes the gap on this task | 19.8% → 97.9% open-ended; out-of-vocabulary 743/1,000 → 0/1,000; 67.1% → 83.7% closed-set |
| The base model's failure is formatting, not knowledge | 743 of 1,000 vanilla answers fell outside the label set |
| Confidence is informative | AUROC 0.972; ECE 0.017 → 0.014 after Platt scaling |
| Confidence supports a safety policy | Reviewing 4.5% of cases cuts silent errors from 21 to 4 per 1,000 |
| The explanations are faithful to the model | 30% flip rate for top-3 SHAP clauses vs 3% random, significant from k = 2, p < 0.001 |
| Behaviour is near-equal across subgroups | Gaps 1.5 pp (sex) and 3.4 pp (age) with overlapping CIs; parity 0.96 and 0.97 |

### Limitations

- **Synthetic data and machine-written summaries.** DDXPlus patients are rule-generated, so the mapping from evidence to diagnosis is cleaner than reality — the main reason a 49-class accuracy of 97.9% is attainable. The summaries are LLM-written and may contain shortcuts a real clinical note would not have. The shortcut flags in `xai_analysis.py` are the search for exactly that.
- **Prompt mismatch.** The application's prediction path reaches 94.1% rather than 97.9%, with 38 out-of-vocabulary answers, because the app defines its own copy of the prompt constant while the evaluation scripts import a shared one. Fix: import one shared prompt, or constrain decoding to the 49 labels.
- **Human-in-the-loop is partly implemented.** Calibrated confidence, the three-zone policy and the live zone display exist. There is no accept/reject control, no decision-reason field and no audit log. The trigger is built; the override and its record are not.
- **Test results not yet reported.** Held-out test accuracy and macro-F1 for vanilla and independent 5k are not reported. Do not copy validation results into a test table.
- **Leakage checks outstanding.** Exact and near-duplicate checks across source splits, and diagnosis mentions in legitimate medical history, still need running. Do not remove legitimate history solely because it mentions a disease.
- **No independent 3k model.** The failed progressive 3k run is not comparable to independent 1k/5k training.

## Live demo

```bash
uv run python src/app_gradio.py --deferral-policy runs/trust/token_5k/deferral_policy.json
```

The app loads a test patient, shows the original evidence and the generated summary, predicts a diagnosis, displays the live token confidence and its deferral zone, and explains the prediction with SHAP. The clinical summary is editable: changing it clears the prediction, so a clause can be removed and the case re-run as a manual counterfactual.

No patient data is sent to an external API; Gradio binds to `127.0.0.1` by default. This is a research demonstration, not clinical software.

> The confidence gauge in the app shows the **live token score**. Calibrated probabilities and zones appear only when a `--deferral-policy` fitted by `evaluate_trust.py` is supplied.

## Reproduce

### Open-ended evaluation

```bash
uv run python src/evaluate_gemma4_diagnoses.py --model-id vanilla

uv run python src/evaluate_gemma4_diagnoses.py \
  --model-id 5000 \
  --adapter-root runs/gemma4_qlora_independent \
  --output-root runs/gemma4_evaluation_independent
```

Held-out test set, same protocol:

```bash
uv run python src/evaluate_gemma4_diagnoses.py \
  --model-id vanilla --split test \
  --output-root runs/gemma4_evaluation_test

uv run python src/evaluate_gemma4_diagnoses.py \
  --model-id 5000 --split test \
  --adapter-root runs/gemma4_qlora_independent \
  --output-root runs/gemma4_evaluation_test
```

Predictions are stored incrementally and reused when an evaluation is rerun with an identical configuration. Results include `predictions.jsonl`, `metrics.json`, per-class classification reports and confusion matrices.

### Confidence, calibration, deferral and subgroups

The deployed model is ~98% accurate, so calibration needs ~1,000 cases per split to contain enough errors. Fit on validation, evaluate on test:

```bash
uv run python src/evaluate_feddx_confidence.py --model-id 5000 --split validate --n 1000 \
  --adapter-root runs/gemma4_qlora_independent
uv run python src/evaluate_feddx_confidence.py --model-id 5000 --split test --n 1000 \
  --adapter-root runs/gemma4_qlora_independent
```

Then, on CPU:

```bash
uv run python src/evaluate_trust.py \
  --calib runs/feddx_confidence/validate/stage-5000/n1000_seed42/predictions.jsonl \
  --eval  runs/feddx_confidence/test/stage-5000/n1000_seed42/predictions.jsonl \
  --output-dir runs/trust/token_5k
```

Outputs: `trust_report.md`, `reliability_diagram.png`, `risk_coverage.png`, `subgroups.png`, `subgroups.csv`, `zones.csv`, `deferral_policy.json`.

The same script accepts closed-set predictions, which contain more errors. Omitting `--eval` splits one file 50/50 into calibration and evaluation halves:

```bash
uv run python src/evaluate_trust.py \
  --calib runs/gemma4_evaluation_closed_set/validate/stage-5000/predictions.jsonl \
  --output-dir runs/trust/closed_set_5k
```

### SHAP faithfulness (GPU)

```bash
uv run python src/shap_faithfulness.py --model-id 5000 \
  --adapter-root runs/gemma4_qlora_independent --n 20
```

Use `--no-flip-test` to skip re-generation, and `--reports-only` to rebuild reports on CPU.

### Contrastive SHAP and shortcut screen (GPU)

```bash
uv run python src/xai_analysis.py --model-id 5000 --split test --per-class 4 --all-errors \
  --adapter-root runs/gemma4_qlora_independent \
  --predictions runs/gemma4_evaluation_test/test/stage-5000/predictions.jsonl
```

`--reports-only` re-runs the alignment and reporting stage without a GPU.

uv add --dev pytest && uv run pytest -q tests

### Note on an earlier SHAP fix

`split_clinical_text` previously failed on the `.\n` after the demographic line, which every summary contains, and fell back to fixed word groups that cut through clauses ("Chest | pain that is"). It now splits on clause boundaries. SHAP results computed before this fix used word groups.
